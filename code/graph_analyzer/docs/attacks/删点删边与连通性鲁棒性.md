# 删点删边与连通性鲁棒性

文档版本：1.0.0；定义核对日期：2026-09-28。

`connectivity_robustness` 汇总**每个整数删除数**后的最大连通分量。它支持无向删边、有向删点和有向删边；无向删点继续使用 `robustness_schneider`。攻击次序属于协议，必须与数值一起保留。这些接口扩充了连通性鲁棒性的计算范围，但不代表已经覆盖所有网络鲁棒性定义。

## 1. 定义、分母与端点

设原始图有 `N0` 个节点、`M0` 条边，目标总数为

\[
T_0=\begin{cases}N_0,&\text{删点},\\M_0,&\text{删边}.\end{cases}
\]

`L_mode(q)` 是累计删除 `q` 个目标对象后，残余图最大指定分量的节点数。注册指标的定义是

\[
R_{\mathrm{mode}}=\frac{1}{T_0}\sum_{q=1}^{T_0}\frac{L_{\mathrm{mode}}(q)}{N_0}
=\frac{\sum_{q=1}^{T_0}L_{\mathrm{mode}}(q)}{T_0N_0}.
\]

- `component_mode='weak'`：有向图忽略边方向后计算连通分量；无向图使用通常的连通分量。
- `component_mode='strong'`：有向图使用强连通分量，即分量内节点两两可沿有向路径互达。
- 两个分母都取**原始图**的数量，不随删除过程改变，也不使用初始最大分量大小 `L_mode(0)`。
- 求和排除 `q=0`，包含 `q=T0`。初始状态仍保存在轨迹中，用于审计。
- 删点结束后没有节点，`L_mode(N0)=0`。
- 删边保留全部节点及孤立节点；当 `N0>0` 且全部边被删除时，`L_mode(M0)=1`。不能把这个端点强制改为零。
- 对同一个图、同一个协议和同一个分量定义，数值越大，表示删除过程中平均保留的最大分量比例越高。不同分母、端点或攻击策略下的值不可直接混用。

初始图可以不连通，公式仍以 `N0` 归一化。因而它同时反映初始连通状态和后续破坏过程；它不是相对于初始最大分量的纯保留率。

| 原始图与攻击 | 使用的指标 | 分量参数 | 解释 |
|---|---|---|---|
| 无向图删点 | `robustness_schneider` | 采用无歧义的最大连通分量观测 | `sum(LCC(1:N0))/N0^2`，保留原有指标身份 |
| 无向图删边 | `connectivity_robustness` | `weak` | 删边最大连通分量离散和 |
| 有向图删点 | `connectivity_robustness` | `weak` 或 `strong` | 本项目显式定义的有向扩展 |
| 有向图删边 | `connectivity_robustness` | `weak` 或 `strong` | 本项目显式定义的有向扩展 |

无向图指定 `strong` 返回 `not_applicable`，避免把相同无向定义重复登记为不同指标。无向删点传给新指标也返回 `not_applicable`，提示使用已有 Schneider 指标。

## 2. 文献定义与项目扩展的边界

Zeng 与 Liu 的 *Enhancing network robustness for malicious attacks*，arXiv:1203.2982v1（2012-03-14），式 (1) 给出删边指标 `Rl=(1/E) sum S(p)`，删除比例从 `1/E` 到 `1`。将 `S(q/E)=LCC(q)/N0` 代入即可得到这里的无向删边求和。原文在该指标的攻击语境中采用**每次更新、优先删除最高边介数**的攻击策略。

本库允许调用者指定随机、外部序列、静态／自适应排序等协议。因此：

- 采用其他协议时，应称为“指定协议下的删边 LCC 离散和”，并报告 `protocol_id`；不要声称重现了原文的攻击实验。
- 原文没有提供这里的有向弱／强连通推广。两个有向版本明确标记为项目定义，版本为 `1.0.0`。
- 同分处理规则也会影响路径。若要复现某篇文献，仍需另外核对其同分策略、图预处理和随机设置。
- Schneider 等人的无向删点公式保持原有身份；它不被重新命名成删边或有向指标。

来源记录：

| 来源 | 固定版本／核对日期 | 在本库中的用途与许可边界 |
|---|---|---|
| `https://arxiv.org/abs/1203.2982` | arXiv:1203.2982v1，2012；2026-09-28 核对式 (1) 与攻击说明 | 由数学定义独立编写 MATLAB 实现，未复制作者代码；不推定论文授权为软件许可证 |
| `https://doi.org/10.1073/pnas.1009440108` | Schneider 等，2011；原注册条目核对于 2026-09-27 | 已有 `robustness_schneider` 的来源，本次未改变其公式身份 |
| `https://www.mathworks.com/help/matlab/ref/graph.conncomp.html` | 本库使用 MATLAB R2024b | 分量计算调用安装的 MATLAB，遵循本机 MATLAB 许可；不重新分发其代码 |

本地已核对的删边论文文本和来源抓取记录位于 项目根目录的 `_local/history/graph_analyzer/validation/followup_sources/edge_robustness.txt` 与同目录 `sources.json`。在线地址用于来源追溯，复现实验时应优先记录固定版本。

## 3. API：无向删边

以下只创建内存中的三节点小图，不读取或规定任何正式图文件格式。

```matlab
cd('code/graph_analyzer'); % 从项目根目录执行
setup_metrics;
ctx = mc.context(sparse(ones(3)-eye(3)),false);
weak = struct('metric_id','largest_component_size', ...
    'parameters',struct('component_mode','weak'));
protocol = struct('target','edge','strategy','external', ...
    'external_sequence',[1 2 3]);
trajectory = mc.attack(ctx,protocol,weak);
result = mc.summarize(ctx,trajectory, ...
    struct('metric_id','connectivity_robustness', ...
    'parameters',struct('component_mode','weak')));
% LCC at q=0:3 is [3 3 2 1]; result.values = (3+2+1)/(3*3) = 2/3.
```

若要设置原文语境中的逐边自适应最高边介数攻击，可显式使用：

```matlab
protocol = struct('target','edge','strategy','ranked', ...
    'ranking','adaptive','recompute_interval',1, ...
    'deletion_mode','single','batch_size',1, ...
    'rank_metric',struct('metric_id','edge_betweenness', ...
                        'parameters',struct('normalized',false)), ...
    'score_order','desc','tie_break','original_id');
```

这里把同分规则设为原始 ID 升序，是明确的实现选择；不把它自动归因于论文。

## 4. API：同一轨迹同时观察弱／强连通

```matlab
ctx = mc.context(sparse([1 2 3],[2 3 1],1,3,3),true);
weak = struct('metric_id','largest_component_size', ...
    'parameters',struct('component_mode','weak'));
strong = struct('metric_id','largest_component_size', ...
    'parameters',struct('component_mode','strong'));
protocol = struct('target','edge','strategy','external', ...
    'external_sequence',[1 2 3]);
trajectory = mc.attack(ctx,protocol,[weak;strong]);
requested = [ ...
    struct('metric_id','connectivity_robustness', ...
           'parameters',struct('component_mode','weak')); ...
    struct('metric_id','connectivity_robustness', ...
           'parameters',struct('component_mode','strong'))];
results = mc.summarize(ctx,trajectory,requested);
% Weak sizes: [3 3 2 1], Rweak=2/3.
% Strong sizes: [3 1 1 1], Rstrong=1/3.
[x,strong_sizes,valid,detail] = mc.attack_curve(trajectory,strong,'states');
```

同一 `metric_id` 有多个参数版本时，单独传名称会触发 `mc:AmbiguousMetric`。`mc.attack_curve` 和重复统计接受精确的 `{metric_id, parameters}` 选择器；还可增加 `metric_version` 选择已保存的历史定义。参数按规范化后的完整结构精确匹配，不做部分字段猜测。

`sampled_curve_auc` 与 `first_threshold_fraction` 使用参数 `metric_parameters` 选择源指标：

```matlab
request = struct('metric_id','sampled_curve_auc','parameters', ...
    struct('metric_id','largest_component_size', ...
           'metric_parameters',struct('component_mode','strong'), ...
           'source','states','interval',[0 1], ...
           'normalize_initial',false));
auc = mc.summarize(ctx,trajectory,request);
```

`metric_parameters=[]` 仅在源指标名称无歧义时可用。AUC 的 `normalize_initial=true` 表示除以初始源指标值；它不等于本指标固定除以 `N0`。

## 5. 完整路径、状态与计算代价

必须同时满足 `full_single_object_trajectory=true`，以及实际删除数恰好为 `0:T0`。比例网格若实际覆盖所有整数删除数也可满足此条件；粗网格、提前停止或固定大批次不能替代完整路径。

| 情况 | 输出／行为 |
|---|---|
| `N0=0` 或 `T0=0` | `undefined`，归一化分母无定义 |
| 轨迹不完整，或图／攻击类型不适用 | `not_applicable` |
| `q=1:T0` 中所选最大分量值不可用 | `not_computed`，不插值、不补零 |
| 轨迹属于其他原始图上下文 | 拒绝，`mc:TrajectoryIdentity` |
| 一个轨迹内源指标定义／版本改变 | 拒绝，`mc:MetricDefinitionMismatch` |

结果 `details` 保存原始分量曲线、按 `N0` 归一化后的曲线、求和端点、两个分母、源指标定义及 `protocol_id`。离散求和本身是 `O(T)` 时间和空间；总攻击成本还包括每个状态的分量计算、残余图映射和可选的排序重算。全路径不自动降采样。

## 6. 验证入口与覆盖边界

测试入口为 `code/graph_analyzer/tests/test_connectivity_extensions.m`（相对于项目根目录）。应核对无向路径、三角形、星图、有向路径和有向环；特别检查强／弱分量差异、删边保留孤立点、最终端点、缺失观测、源参数消歧和错误原图身份。小图解析预期包括：三节点路径逐边删的值 `1/2`、三角形逐边删的值 `2/3`、四节点星图逐边删的值 `1/2`。

本文给出验证要求和入口，不单独宣称本轮测试通过数量；以实际生成的验证报告为准。
