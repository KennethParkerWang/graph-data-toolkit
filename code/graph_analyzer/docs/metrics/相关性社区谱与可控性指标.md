# 相关性社区谱与可控性指标

Definition/implementation version: **1.0.0**. The executable registry is
`registry/advanced.json`; this document describes the 17 functions in that fragment.
Each function accepts `ctx` from `mc.context` and an optional scalar parameter
struct. Persisted graph loading remains the graph-generation task's responsibility.
Only simple unweighted topology is inferred from `ctx.A`. A directed entry
`ctx.A(i,j)=1` means **i -> j**.

## Definition and parameter catalog

In the formulas below, N is the current node count and M counts an undirected
edge once. Partitions and explicit state matrices use `ctx.node_ids` order.
All algorithms here are deterministic; no random seed is consumed.

| metric_id | Definition and output | Applicability / parameters |
|---|---|---|
| `degree_assortativity` | Pearson correlation of the endpoint degrees along arcs; undirected edges contribute both orientations. Scalar. | Directed `source_degree`, `target_degree` each `in`/`out`, defaults `out`/`in`. All four combinations are selectable. No edges or zero endpoint variance: undefined. |
| `average_neighbor_degree` | Mean target degree over selected **distinct** neighbors. Node vector. | `neighbor_mode=out/in/all`, default out; `target_degree=total/in/out`, default total. `all` is the union of predecessors/successors, so a reciprocal neighbor appears once. Undirected modes all reduce to ordinary degree. An empty neighborhood is NaN with invalid mask. |
| `reciprocity` | Reciprocal arc count / M. Scalar. | Directed only; one mutual pair contributes two arcs. No arcs: undefined. |
| `rich_club` | `2 E_{degree>k}/[N_{degree>k}(N_{degree>k}-1)]`. Distribution indexed by threshold. | Undirected, unnormalized. Explicit unique nonnegative integer `thresholds`, or default `0:max(degree)`. Fewer than two selected nodes: undefined entry. No reference-graph sampling is hidden in this function. |
| `modularity` | Undirected: `sum_c[L_c/M-gamma*(K_c/(2M))^2]`. Directed: `sum_c[L_c/M-gamma*K_out,c*K_in,c/M^2]`. Scalar. | Required integer `partition` labels, one per node; `resolution=1` by default, positive. No edges: undefined. |
| `community_sizes` | Node count per supplied community label. | Required `partition`; labels may be any finite integers and are sorted on the output axis. Empty graph/partition gives a valid empty distribution. |
| `greedy_modularity_communities` | Start singleton communities and repeatedly merge the pair with greatest positive modularity gain. Node vector of representative original node IDs. | Both graph types; `resolution=1`, `gain_tolerance=1e-12`, `max_nodes=2000`. Ties choose the smallest representative-ID pair. Stops when gain <= tolerance. Stores achieved Q, sizes and merge history; a heuristic with no global-optimum claim. No edges: undefined. |
| `adjacency_spectrum` | All eigenvalues of A. Distribution. | Both graph types; directed results can be complex. Ascending real part then imaginary part; no node interpretation for eigenvalue-index axis. Empty graph: valid empty spectrum. |
| `adjacency_spectral_radius` | `max(abs(eigenvalues(A)))`. Scalar. | Both types; no-node graph undefined, edgeless nonempty graph zero. |
| `laplacian_spectrum` | Sorted eigenvalues of unnormalized `L=diag(degree)-A`. Distribution. | Undirected only; empty spectrum valid. Does not reinterpret a directed Laplacian. |
| `algebraic_connectivity` | Second-smallest eigenvalue of L. Scalar. | Undirected, N>=2; N<2 undefined. Component test returns exact zero for disconnected topology. |
| `natural_connectivity` | `log(sum(exp(lambda(A)))/N)`. Scalar. | Undirected, N>0. Stable log-sum-exp avoids overflow; edgeless nonempty graph zero. |
| `effective_resistance` | Within a component, `(e_i-e_j)'*L^+*(e_i-e_j)`; between components +Inf. Matrix with original node IDs on both axes. | Undirected unit resistors; diagonal zero. +Inf is a valid extended-real result, with mask true. Not applicable to directed topology. |
| `kirchhoff_index` | `sum_{i<j}R_ij`; connected equivalent `N*sum_{k=2}^N(1/lambda_k(L))`. Scalar. | Unordered distinct pairs. N=0 undefined; N=1 zero; disconnected nontrivial graphs +Inf with valid mask. |
| `structural_driver_count` | Minimum **general independent input channels**, `max(1,N-matching_size)` for N>0. Scalar. | Directed independent free-parameter structure. N=0 returns zero. General-input fanout and source-SCC accessibility are essential; details below. |
| `structural_dedicated_feasibility` | Whether the specified independent dedicated inputs satisfy input accessibility and a full augmented bipartite matching. Boolean scalar. | Directed only; required `driver_node_ids` are unique existing original node IDs. Tests a supplied placement; does not optimize actuator placement. Empty system is vacuously feasible. |
| `exact_numeric_driver_count` | Numerical evaluation of `max_lambda[N-rank(S-lambda I)]`. Scalar. | Required finite real N-by-N `state_matrix=S`; unrestricted real input matrix B. `rank_tolerance=1e-9`, `eigenvalue_tolerance=1e-7`, `max_nodes=2000`. N=0 returns zero. This is not the count for dedicated-node inputs. |

All seven spectral/electrical functions have an
explicit `max_nodes=2000` guard. Exceeding it returns `not_computed`, and never
substitutes a truncated eigensystem. Full eigenvalue computation is cubic with
quadratic storage. Effective resistance solves each connected component using
`Z=(L+ones(n)/n)\eye(n)` and obtains resistances from `diag(Z)+diag(Z)'-2Z`.
Tiny negative roundoff is clipped to zero; larger negative values raise an error.
The count of numeric control inputs can require one SVD per eigenvalue group,
so its worst-case cost is O(N^4). Select these metrics explicitly for small graphs.

## The two control problems are different

`structural_driver_count` concerns the generic controllability of
`xdot=A_state*x+B*u`, with `A_state` patterned as `ctx.A'` and every permitted
entry a free independent parameter. It constructs a general B pattern: separate
input columns cover unmatched target vertices, and an existing input fans out
to any source strongly connected component still lacking an input. The stored
`input_pattern` and row node IDs show this accessibility wiring. The minimum
number counts independent **channels**, not the number of actuated nodes.

For example, two disconnected directed cycles have perfect matching and need
one general input channel that connects into both cycles. One dedicated actuator
in the first cycle leaves the second inaccessible. The test suite verifies this
case using `structural_dedicated_feasibility`. It also verifies a directed path,
outward star and edgeless graph. Undirected graphs are not silently converted to
independent bidirectional parameters. The structural conditions and the dedicated
placement distinction follow [Liu et al. (2011)](https://www.nature.com/articles/nature10011)
and [Pequito, Kar & Aguiar (2016), author manuscript](https://pages.up.pt/~up519521/publications/TAC2016_StrSys.pdf).

`exact_numeric_driver_count` uses the explicitly supplied **fixed** matrix S.
It does not infer weights, self-dynamics or a numeric matrix from the graph.
The caller is responsible for specifying the intended matrix; its complete
values remain in metric parameters and are part of run identity. Rows/columns
must match `ctx.node_ids`. A numeric S can include self-dynamics and must not be
confused with the graph's binary adjacency. The minimum count permits unrestricted
real B and follows maximum geometric multiplicity, as in
[Yuan et al. (2013)](https://www.nature.com/articles/ncomms3447).

Our numerical policy is explicit: `scale=max(1,norm(S,2))`, singular values are
nonzero when greater than `rank_tolerance*scale`, and eigenvalue groups use
complete-link distances no greater than `eigenvalue_tolerance*scale`.
Each group is represented by its mean. Geometric multiplicity must lie between
one and its cluster size; otherwise the function returns `not_computed` with
diagnostics. The result records eigenvalues, groups, multiplicities and absolute
thresholds. Close eigenvalues, ill-conditioned matrices and defective eigenvalues
remain tolerance-sensitive; this is a numerical result, not a symbolic certificate.
The tests include `S=diag([1,1,2])`, whose required count is two although
`N-rank(S)` is zero, plus a Jordan block and a real matrix with complex eigenvalues.

## Reference implementations, provenance and license

The MATLAB code in this module is newly written from the stated formulas and
algorithmic principles. No third-party source code was copied or translated
line by line. We inspected the following **NetworkX 3.5** source implementations
before implementation and use their public APIs for independent fixtures:

- [Degree correlation](https://networkx.org/documentation/networkx-3.5/_modules/networkx/algorithms/assortativity/correlation.html): endpoint Pearson definition; Newman (2003), Foster et al. (2010).
- [Average neighbor degree](https://networkx.org/documentation/networkx-3.5/_modules/networkx/algorithms/assortativity/neighbor_degree.html): reference for directed in/out modes. Our documented distinct-union `all` mode differs from NetworkX's multiplicity-based `in+out`; isolated means are undefined here instead of zero.
- [Reciprocity](https://networkx.org/documentation/networkx-3.5/_modules/networkx/algorithms/reciprocity.html): reciprocal-arc fraction.
- [Rich club](https://networkx.org/documentation/networkx-3.5/_modules/networkx/algorithms/richclub.html): McAuley, da Fontoura Costa & Caetano (2007). Our explicit threshold axis retains undefined entries instead of omitting them.
- [Modularity](https://networkx.org/documentation/networkx-3.5/_modules/networkx/algorithms/community/quality.html) and [greedy modularity source](https://networkx.org/documentation/networkx-3.5/_modules/networkx/algorithms/community/modularity_max.html): community-summed objective and positive-gain agglomeration. Our dense pair scan uses documented representative-ID ties and stops at a positive tolerance; it is not a performance-equivalent port of the heap algorithm, nor guaranteed to reproduce tied NetworkX partitions.
- [Spectral functions](https://networkx.org/documentation/networkx-3.5/_modules/networkx/linalg/spectrum.html) and [resistance source](https://networkx.org/documentation/networkx-3.5/_modules/networkx/algorithms/distance_measures.html): full spectra and Klein & Randic resistance distance. NetworkX requires connected graphs for its resistance API; we apply the formula componentwise and explicitly use +Inf across components.

Inspected NetworkX 3.5 code is
[BSD-3-Clause](https://raw.githubusercontent.com/networkx/networkx/networkx-3.5/LICENSE.txt).
Its license permits attributed redistribution subject to its conditions, but this
module does not redistribute that source. MATLAB `eig`, `svd`, graph components
and linear solvers are runtime calls under the user's MATLAB license, tested
with R2024b. The maximum-matching helper is an independent breadth-first
augmenting-path implementation, compared against MATLAB's independent
[sprank](https://www.mathworks.com/help/matlab/ref/sprank.html) implementation.

Natural connectivity follows
[Wu, Barahona, Tan & Deng (2010)](https://arxiv.org/abs/1009.3430),
with the log-mean-exp definition evaluated without sampling.
Numerical eigensystems use the documented
[MATLAB eig contract](https://www.mathworks.com/help/matlab/ref/eig.html).
Reference retrieval date: 2026-09-27. Publication licenses are not treated as
permission to reuse author code; no author code was available or reused here.

## Verification and usage

Run `test_advanced` with this folder and `tests/` on the MATLAB path. It checks
path, ring, star, complete graph, isolates, disconnected graph, no-node and
single-node cases; four directed degree-correlation combinations; original-ID
permutation consistency; spectra and resistance analytic values; and control
input-model counterexamples. It compares the matcher with `sprank` on all 64
loop-free directed graphs on three vertices, and routes all 17 metrics through
`mc.compute`.

`validation/generate_advanced_reference.py` uses pinned NetworkX 3.5 and installed
NumPy/SciPy to build `validation/advanced_reference.json`: 7 graphs and 86 metric
comparisons. Fixture generation performs no production graph loading. The MATLAB
test consumes these fixtures at relative tolerance 1e-9. Keep the JSON file with
the suite; the test reports zero reference comparisons if the optional file is
missing, rather than claiming that independent comparison ran.

Example selections:

```matlab
ctx = mc.context(sparse([0 1 0;0 0 1;0 0 0]),true);
selection(1) = struct('metric_id','structural_driver_count','parameters',struct());
selection(2) = struct('metric_id','degree_assortativity', ...
    'parameters',struct('source_degree','in','target_degree','out'));
results = mc.compute(ctx,selection);
% Explicitly fixed numeric dynamics, allowing self-dynamics:
r = mc.metrics.exact_numeric_driver_count(ctx, ...
    struct('state_matrix',diag([1 1 2]),'rank_tolerance',1e-9, ...
           'eigenvalue_tolerance',1e-7));
```

## Extensions deliberately unavailable

- Minimum dedicated actuator placement is not implemented; it requires optimizing
  unmatched-vertex coverage of source SCCs. A single arbitrary maximum matching
  cannot certify that optimum. Only fixed dedicated placement feasibility is available.
- Restricted B, target controllability, control energy and finite/infinite-horizon
  Gramians require explicit B/output/time/stability data and separate definitions.
- Normalized rich club and community significance require a named reference-graph
  ensemble, sample count and random seed, obtained via the graph-generation API.
- Directed Laplacians, directed natural-connectivity extensions and directed
  resistance each require a separately chosen definition; none is silently inferred.
- Approximate spectra or sparse large-scale controllability estimators need separate
  metric IDs, numerical error policies and validation before becoming available.

These extensions have no success-returning placeholder functions.
