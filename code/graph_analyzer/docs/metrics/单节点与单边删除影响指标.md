# 单节点与单边删除影响指标

`deletion_impact` version 1.0.0 computes `f(G)-f(G without object i)`, independently for each node or edge. A required `base_metric` selection identifies the graph scalar and its parameters. `relative=true` additionally divides by `f(G)`. Positive values mean deletion reduced the selected quantity; this is not automatically “damage” when the quantity's scientific interpretation differs.

The vulnerability principle is described by [Latora & Marchiori, Physical Review E 71,015103 (2005)](https://journals.aps.org/pre/abstract/10.1103/PhysRevE.71.015103), [author preprint](https://arxiv.org/abs/cond-mat/0407491). This generalized implementation is original formula-based MATLAB code, with no upstream source copied and no claim that arbitrary base metrics inherit the paper's efficiency interpretation.

Input is a validated `mc.context`; `target=node` produces node IDs and `target=edge` produces canonical original edge IDs. Each residual context remaps local node indices while preserving original IDs. Base values, residual values, per-object invalid reasons and normalization choice are saved in `details`. An invalid/nonfinite baseline returns undefined; invalid residual metrics produce false masks at those objects; zero baseline invalidates relative values. Empty objects produce an empty vector. Fixed numeric state matrices are rejected because updating them under deletion needs an explicit scientific policy.

This is exact repeated computation, costing `K*(O(N+M)+C_base)`, with `max_objects=200` by default. No approximation occurs when the limit is exceeded. Unlike an attack trajectory, each deletion starts from the same graph. Verified in `tests/test_io.m`: edge-count impact `[1;1;0]` on one edge plus an isolate, original edge-ID mapping, and zero-baseline relative masks. See the main validation report for pass status.
