# 原始图交接与读写示例

任务2/3以[graph_schema_v1.md](../graph_schema_v1.md)为正式依据。当前算法版本2.1.0，批量配置版本2；原2.0生成数据仍按保存的身份读取。不要继续读取早期draft或旧的A/N/edge_list/meta四字段MAT。

## 任务2：MATLAB指标

```matlab
addpath('code/graph_builder');
setup_generators;
root = 'code/graph_builder/examples/schema_v1';
records = gg_io_read_manifest(root);
record = records(1);
sample = gg_io_read_graph(fullfile(root,record.path), record);
% sample.A, sample.N, sample.M, sample.directed
% sample.edge_list行号即原始edge_id，node_id为1..N。
```

传入索引record才能同时检查文件字节校验。`source_edge_order`是可选字段；缺失时不得用排序边序冒充来源边序。删点删边后继续保留原始ID。指标写独立metrics文件，不回写图MAT。

社区标签为`sample.meta.attributes.community`，每行对应原节点；坐标为`sample.meta.attributes.positions`，行对应原节点、列对应空间维度。先检查该模型是否有此字段。

## 任务3：Python训练数据

使用`scipy.io.loadmat(path, mat_dtype=True, struct_as_record=False, squeeze_me=False)`。稀疏logical在部分SciPy版本读作uint8，先验证非零值为1再转bool。保留N，不能用最大边端点推断节点数；无边图edge_list为(0,2)。

独立读取及hash校验例子为[verify_graph_io.py](../../validation/verify_graph_io.py)。graph_id对保存的recipe_json原文做UTF-8 SHA-256，不能先用Python重新排版JSON。无向边表仅一份u<v，转双向消息传递边时另保留原始edge_id映射。

五张[样例](../../examples/schema_v1)覆盖无向、有向互惠弧、孤立点、无边、单节点、附加属性、来源边序和派生关系。这些是格式测试数据，不用于训练。

## 生产数据

`generate_graph_batch`写项目`datasets/<dataset_id>/`；图索引为`manifests/graphs.jsonl`。任务2写metric_sets/protocols配置及metrics结果，任务3写splits与training。三者不要修改彼此的原始存档。

本任务只改graph_builder及其中验证样例，没有改graph_analyzer或dataset_builder。任务2现有read_graph适配器、任务3现有source适配器是否已经绑定正式接口，由各自任务按这份交接完成。不能仅凭schema文件存在认定适配已通过。
